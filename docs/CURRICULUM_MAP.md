# Curriculum map

Status: canonical. This file maps calendar weeks to sprints, taught topics, capstone deliverables and acceptance criteria for both cohort branches.

## Why two branches

The same platform is built twice, on two branches derived from one reference implementation. `us-ireland` runs twelve calendar weeks with the capstone in Sprints 3 to 11. `india` runs nine, with the capstone in Sprints 3 to 10 and a separate deployment week supported by Fidelity alumni. The India cohort are returning interns: they hold the fundamentals already, so their modules start at applied depth and their taught days per sprint are shorter, but the components they build are the same components in the same order.

Week folder names encode the calendar week and the component. The component slug is identical across branches for the same sprint, so `week-04-trade-database` on `us-ireland` and `week-02-trade-database` on `india` hold the same Sprint 3 deliverable. Only the week number differs.

## US and Ireland, weeks 4 to 12

Twelve calendar weeks beginning with an induction week. Sprints 1 and 2 carry no capstone deliverable: they cover environment, Git, agile practice, OWASP and Secure Code Warrior, and they are taught without Copilot. The capstone starts in week 4.

Foreign keys and check constraints present, including a unique constraint on the order idempotency key. At least three indexes justified by a named query. Seed data loads with one command and covers active, suspended and closed accounts. Every team member can walk the ER diagram unaided. Converges on `contracts/database-schema.sql` without having been given it first. |

## India deployment addendum: cloud week

India has no Sprint 11. Cloud deployment runs as a separate four and a half day week after the capstone sprint, delivered as Fidelity experiential learning and supported by Fidelity alumni rather than by Neueda instructors. Use the folder `week-10-cloud-deploy` for its material so the slug matches `us-ireland`.

| Item | Detail |
|---|---|
| Duration | Four and a half days |
| Delivered by | Fidelity, with alumni support. Neueda supplies the material and the acceptance criteria only. |
| Prerequisite | The Sprint 10 build passing its own tests, and a working local Docker Compose stack |
| Scope | Docker setup review, AWS account and IAM basics, AWS CLI, S3 static hosting, origin access control, CloudFront, deployment automation |
| Deliverable | The Angular build deployed to a private S3 bucket behind CloudFront, with an automated build, upload and invalidate cycle, and the link shared with the cohort |
| Acceptance criteria | Identical to `us-ireland` week 12, excluding the final showcase. Application reachable over HTTPS through CloudFront. Direct S3 access denied. Origin access control configured. Deployment automated in one script or workflow. Authenticated flows verified against the deployed front end. IAM scoped to the bucket and distribution, no long-lived keys committed. |
| Assessment | Capstone deployed and link shared, assessed asynchronously against the criteria above. The demonstration and assessment for the platform itself happened in week 9. |

Two constraints apply because the week is alumni-supported. Material must be self-contained, because there is no instructor to fill gaps in the room. Every step must work from a printed runbook with no live Neueda support, so write the runbook to be followed literally and test it end to end before delivery.
